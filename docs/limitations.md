# Limitations

- This is an on-demand comparison. It cannot observe transient changes between scans, identify an editor, attribute intent, repair files, or recover lost data.
- SHA-256 and Ed25519 assume trustworthy implementations and hosts. Baseline creation requires independently trusted inputs. Key substitution, private-key compromise, and replay of an older valid manifest require controls outside this tool.
- A directory walk is not a point-in-time filesystem snapshot. Files can change after an individual check. A sufficiently privileged writer may restore bytes and metadata between observations. Quiesce writers or verify an independently obtained, read-only snapshot when consistency across files matters.
- Reparse points, detected filesystem-device crossings, links, and special entries are rejected. Windows lacks the POSIX directory-descriptor walk used here. Concurrent replacement of parent directories is a residual race, particularly for control paths and output publication. Use trusted, stable parent directories. Same-device bind mounts and network filesystems presented as local paths can be indistinguishable. Use an operator-selected local filesystem.
- Only named regular-file contents and lengths enter the manifest. Permissions, ownership, timestamps, empty directories, hard-link topology, alternate data streams, and extended attributes are outside the comparison. Reads can update access times under the filesystem's mount policy.
- Discovery normalizes names to Unicode NFC. Ambiguous names and names without a portable representation prevent a complete inventory. Byte, depth, and entry budgets bound memory. Very large collections can exceed them. Hashing still requires reading each complete file and has no fixed elapsed-time budget.
- An inaccessible subtree may contain expected files. The report marks the error and suppresses missing-file claims inside that subtree. Investigate incomplete results before interpreting any other findings.
- Manifests and reports can disclose filenames, sizes, and content fingerprints. Protect them separately. Maintain backups and encryption as the dataset requires.
- POSIX publication requires a filesystem supporting hard links. Output is published exclusively after the temporary file is flushed. A crash can leave a temporary file, one half of a keypair, or a directory entry whose persistence is uncertain. Existing output is never intentionally replaced.
